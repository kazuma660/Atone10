# 技術スタック選定

## 決定内容
**Vite + React + Canvas API** を採用する。

## 選定理由

### なぜ React か
- HUD（バッテリー表示・フロア表示）をDOMコンポーネントとして管理できる
- Canvas（ゲーム描画）と UI を明確に分離できる
- 状態管理（useState / useRef）でゲーム状態を扱いやすい

### なぜ Vite か
- Vercel が自動検出するため `vercel --prod` 一発でデプロイできる
- ホットリロードにより開発中の確認サイクルが速い
- `import/export` によるファイル分割が可能（entities・systems・effects を別ファイルに分けられる）
- `npm create vite@latest` で環境構築が数分で完了

### なぜ Canvas API か
- 企画案 `01_AI_Request.md` に明示的に指定されている
- `requestAnimationFrame` ループで毎フレーム描画を直接制御できる
- ライトのちらつき・ノイズオーバーレイ・lerp カメラなど低レベル描画が必要なため

## 比較検討したフレームワーク

| フレームワーク | 採用可否 | 理由 |
|--------------|---------|------|
| Vite + React + Canvas | **採用** | 企画案指定・Vercel 相性・ファイル分割可能 |
| Phaser 3 | 不採用 | 企画案外・バンドルサイズ大・学習コスト発生 |
| 純粋 HTML + Canvas | 不採用 | ファイル分割不可・規模拡大で管理困難 |

## デプロイ先
**Vercel**（`vercel --prod`）
- `vite.config.js` の `outputDirectory: dist` を自動認識
- 追加設定不要
